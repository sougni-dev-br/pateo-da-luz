1) Assinatura dos callbacks (webhook em Produção)

Nos testes de sandbox, os callbacks POST que chegam ao nosso Endereço do webhook NÃO trazem nenhum campo sign — nem no envelope JSON nem em cabeçalhos HTTP. Antes de subirmos para Produção precisamos implementar a validação. Perguntas:

  • Em Produção, os callbacks são assinados?
  • Se sim, em que lugar a assinatura viaja? (cabeçalho HTTP tipo X-Sign/X-Signature/Signature/Authorization, ou dentro do corpo JSON?)
  • Qual algoritmo é usado? (MD5, HMAC-SHA256, outro?)
  • Quais campos entram no cálculo, em que ordem, e como são concatenados? (ex: app_id + timestamp + body + app_secret?)
  • Como o timestamp é serializado? (segundos unix, milissegundos, ISO 8601?)
  • Existe tolerância de expiração entre o timestamp e a chegada da requisição para rejeitar callbacks antigos (proteção contra replay)?

2) Parâmetro sign em requests POST para a API da 99

Na documentação (YAML OpenAPI), alguns endpoints exigem sign + timestamp + app_id no corpo da requisição. Exemplo: POST /v1/shop/shop/list. A descrição do campo apenas diz "Signature generated as explained above", mas não encontramos a explicação nas seções do portal: Introduction / Tools Introduction / Basic Process Overview / Testing The Integration / Before Coding / FAQ.

Poderiam nos indicar onde consultar a especificação exata do cálculo do sign? Ou, de preferência, enviar diretamente um trecho de código de exemplo (em qualquer linguagem: PHP, Python, JavaScript, Java, curl) mostrando como calcular a assinatura?
